# AI-CRM для агентств недвижимости — one-pager

> Рабочее название не выбрано. Статус: черновик до customer discovery (см. `interview-script.md`).

## Проблема

Агенты ненавидят заполнять CRM. Данные о клиентах живут в мессенджерах, заметках и голове агента, поэтому:
- клиенты «остывают» — им забывают написать;
- брони истекают незамеченными, залоги теряются в переписке;
- руководитель не видит реальную воронку.

Универсальные CRM (amoCRM, Битрикс24) этого не решают: ввод данных остаётся ручным.

## Сегмент

Небольшие и средние агентства Санкт-Петербурга (5–50 агентов), вторичка и новостройки.

| Роль | Чего хочет |
|------|-----------|
| Агент | Меньше рутины, не терять клиентов |
| Руководитель агентства | Видеть воронку и брони, не терять комиссию |
| Клиент (покупатель) | Быстрые ответы, подходящие варианты |

## Решение — CRM, которую заполняет ИИ

### В MVP

| Фича | Что делает |
|------|-----------|
| Карточка из хаоса | Агент вставляет переписку/заметку → ИИ создаёт клиента и запрос (бюджет, район, комнаты, сроки, ипотека) |
| Подбор объектов | Запрос клиента ↔ база объектов агентства, ИИ объясняет, почему подходит |
| Следующий шаг | «Клиенту не писали 5 дней» + черновик сообщения |
| Воронка | Новый → Подбор → Показ → Бронь → Сделка |
| Брони и залоги | **Учёт**, не приём денег: тип (бронь у застройщика / аванс / задаток), сумма, у кого деньги, срок, статус, напоминание до истечения |

### Не в MVP (roadmap)

Приём платежей, телефония, интеграции с Авито/Циан и системами застройщиков, документы и договоры, ипотечные заявки, роли и права, мобильное приложение.

## Гипотезы (проверяем на интервью)

1. Агент тратит на заполнение CRM ≥ 30 мин в день и делает это неполно.
2. Агентства теряют клиентов из-за забытых follow-up.
3. Брони и залоги ведутся в Excel/мессенджерах, истечение брони — реальная проблема.
4. Руководитель готов платить за инструмент, если он экономит время агентов.

## Метрики успеха MVP

| Метрика | Цель |
|---------|------|
| Время создания карточки клиента | < 1 мин (против ручного ввода) |
| Точность извлечения полей ИИ | ≥ 85% полей без правок |
| Доля клиентов без касания > 7 дней | снижение |
| Брони, истёкшие без реакции | 0 |

## Риски

| Риск | Вероятность | Влияние | Ответ |
|------|-------------|---------|-------|
| Приём залогов = платёжное регулирование | Высокая | Высокое | Только учёт, деньги вне системы |
| Персональные данные клиентов (152-ФЗ) | Высокая | Высокое | В демо только фейковые данные; для прода — хранение в РФ, согласия |
| ИИ ошибается при извлечении данных | Средняя | Среднее | Агент подтверждает карточку перед сохранением |
| Рынок занят универсальными CRM | Высокая | Среднее | Клин — автозаполнение ИИ, а не «ещё одна CRM» |
| Гипотезы не подтвердятся на интервью | Средняя | Высокое | Пивот фичи до начала разработки |

## План

1. Customer discovery: 5–7 интервью с агентствами.
2. Уточнение one-pager по итогам.
3. MVP с фейковыми данными (ИИ сначала в режиме заглушки).
4. Демо + кейс в портфолио.
